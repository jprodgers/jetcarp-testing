What the code says (read, not changed): `host stop` returns once the host's port has closed (gone_soon,
host_cmd.rs:594-603); a new host takes the single-instance lock host.lock in its runtime folder and, if that is
held, prints "jetcarp-host: the JETCARP background host is already running" and exits 3 (jetcarp-host lib.rs:72-90,
191-197). A detached host's stderr goes nowhere, so a host that ended at once would look exactly like this. Each
test has its own runtime folder (with_env sets JETCARP_RUNTIME_DIR), so the tests share no lock; on Windows they do
share the data folder (HOME does not move AppData), which the host tests did not write to here.
